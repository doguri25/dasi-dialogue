신청서의 체크·결정·진입 제한은 후속 요청으로 제거했습니다. 이전 신청서 검증 항목은 당시 구현의 기록입니다. 현재 흐름은 아래 ‘신청서 간소화·사전모임 안내 순서’를 따릅니다.

## AI 오류 구분·학생 발언별 선택지·모바일 대화창 이동

- 원래의 일반 오류 문구는 여러 HTTP 실패를 같은 문장으로 반환하던 경로에서 발생함을 코드로 확인. 사용자의 실제 제공사·HTTP 응답·계정 상태는 확인하지 못했으므로 원래 장애를 특정했다고 주장하지 않음.
- 원래 제공사 이름과 HTTP 번호를 표시. 인증·결제·할당량·모델·요청 제한·서비스 오류를 구분하며 원문/키는 노출하지 않음.
- 500·502·503·504·529는 전체 60초 한도 안에서 최대 한 번 재시도. Retry-After가 3초보다 길거나 처리 시간이 부족하면 바로 오류 표시. 모의 529/503/500의 복구, 반복 실패, 402 결제, 400 잔액, 429 할당량 및 일반 한도, 인증·모델 오류, 출력 길이 중단 검사.
- 역할 프롬프트가 방금 생성한 학생 대사에 맞는 teacherChoices 4개를 함께 요청. 서버가 선택지를 검증하고 브라우저가 해당 응답과 함께 보관함. 누락·중복·잘못된 선택지는 발언 참고 질문으로 보완하며 유효한 학생 대사를 버리지 않음.
- 선택지의 상대별 사전면담 분리, 단계별 전환, 다음 답변 후 갱신, 저장·재개 확인. UI용 선택지와 코치 객체는 다음 API 요청의 대화 문맥에서 제외.
- 시나리오 분기가 학생 발언을 인용한 부분의 ‘쉬어도’를 교사의 발문으로 오인하던 회귀 수정. 인용 이후의 질문으로 분기하며 실제 교사의 강압 표현은 그대로 감지.
- Chrome 320 / 390 / 768px에서 선택 즉시 대화창·전송 버튼이 보이는 위치로 이동. 선택만으로 전송하지 않음. 긴 문장 전체 보기, 다시 고르기, 전송 후 최신 답변 이동, HTTP 529 모의 실패 후 선택 보존·재전송, reduced-motion 확인. 1440px에서는 선택으로 화면 이동하지 않음.
- 스크린샷 `mobile-selection-preview.png`, `mobile-service-error.png`, `contextual-choices-desktop.png` 육안 확인. 모든 API 호출은 모의 응답이며 실제 스마트폰·사용자 API 계정 호출은 수행하지 않음.
- 최종 Node 단위·HTTP 검사 23개 통과. `browser.mjs`, `responsive.mjs`, `intake-browser.mjs`, `followups-browser.mjs` 통과. 페이지 오류 없음.
