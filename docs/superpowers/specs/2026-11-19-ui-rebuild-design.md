# 다시, 대화 v1.0 화면 다시 짓기 설계

## 1. 무엇을, 왜

지금 화면(v0.9까지)을 폐기하고, PC와 휴대전화의 모든 화면을 처음부터 다시 짓는다.
사용자의 기준은 하나다: **클릭 수와 스크롤 수를 줄이고, 쓸데없이 확인을 거치지 않게 한다.**
사용자는 단계 관문(아래 3.3)만 고르고 나머지 판단을 설계자에게 맡겼다. 아래의 "설계자 판단"은 모두 그렇게 정한 것이다.

지금 클릭 수(줄일 대상):
- 연습 시작: 바로 연습 시작 → 조건 창 → 시작 → 신청서 → 사전모임 시작하기 (4번)
- 질문 하나 보내기(PC): 카드 → 문장 창 → 이 문장 선택하기 → 보내기 (3번)
- 다음 단계: 진행 확인 열기 → 체크 4개 → 다음 단계로 (6번)
- 저장: 매번 기록 저장 (자동 저장 없음)
- 마치기: 모임 마치기 → 결과 고르기 → 확인 (3번)

## 2. 원칙

1. **확인 대신 되돌리기.** 누르면 바로 일어나고, 잘못 눌렀으면 되돌린다(질문 되돌리기는 이미 있음).
2. **한 화면.** 연습실·회고·첫 화면은 PC와 휴대전화 모두 페이지 스크롤 없이 한 화면에 들어온다. 긴 내용(대화, 사례 목록, 노트)은 그 칸 안에서만 스크롤한다.
3. **창(대화 상자) 없이.** 고르기·확인·결과 선택 창을 없애고, 그 자리에서 바뀐다. 남는 창은 설정, 전체 대화, 신청서 전문처럼 "읽으러 여는 것"뿐이다.
4. **기본값으로 시작.** 고를 것이 있으면 가장 흔한 값으로 먼저 시작하고, 바꾸고 싶을 때만 바꾼다.

## 3. 화면

### 3.1 틀
- 모든 화면 위에 앱 막대 한 줄(56px): 로고(첫 화면) · 사례 · 기록 · 도움말 · 설정(톱니). 휴대전화도 같은 막대(아이콘+짧은 글자). 왼쪽 레일과 아래 고정 메뉴는 없앤다.
- 연습실에서는 앱 막대 대신 연습실 머리줄을 쓴다(3.3).
- 새 시각 체계(이전 "토킹피스" 폐기): 따뜻한 종이 바탕(#f6f4ef), 흰 면, 잉크 글자(#1d2433), 행동 색 하나(청록 #2f7d6d), "지금"을 뜻하는 노랑(#f5c34b)은 아주 드물게. 학생·보호자 색(세이지·연보라·하늘)은 얼굴·의자와 맞추기 위해 유지. 단추는 납작한 둥근 모양(눌리는 턱 없음). Pretendard.

### 3.2 첫 화면(사례)
- PC: 왼쪽 좁은 칸에 **이어서 하기**(마지막으로 하던 연습, 한 번 누르면 그 자리로)와 **바로 시작**(입문 사례·협력적 대화로 즉시 연습실), 연습 순서 세 줄. 오른쪽에 검색, 필터 한 줄(학교급·난도 칩, 주제), 사례 카드 격자(이 칸만 스크롤).
- 사례 카드: 제목, 학교급·난도·주제, 조건 칩 4개(협력 · 교착 · 중단 · 미이행). **카드를 누르면 협력적 대화로 바로 시작, 조건 칩을 누르면 그 조건으로 바로 시작.** 시작 창 없음.
- 첫 화면의 3D 대화실 미리보기는 뺀다(처음 그리는 부담, 시선 분산). 3D는 연습실에서만.
- 휴대전화: 이어서/바로 시작 → 검색·필터(가로로 미는 칩) → 카드 목록.

### 3.3 연습실(사전·본·사후모임)
신청서 관문(intake)을 없앤다: 시작하면 곧바로 사전모임이고, 신청서는 노트와 대화 맨 위의 문서 카드로 늘 볼 수 있다(열람 시각은 시작 시각).

**PC(가로 1100 이상) — 세 칸**
- 머리줄: ← 사례 · 사례 제목·조건 · 단계 표시(사전 · 본 · 사후, 지금 단계 강조) · 자동 저장 표시 · 마치기.
- 가운데: 위에 무대(3D), 무대 왼쪽 위에 대화 상대 얼굴(누르면 바로 바뀜, 무대의 캐릭터를 눌러도 됨), 목소리 켜기 아이콘. 그 아래 대화 기록(칸 안 스크롤). 맨 아래 질문 칸.
- 오른쪽 노트(340px, 늘 펼침): ① 이번 단계에서 확인할 것(체크 줄)과 **다음 단계로**(다 되면 눌림) ② 합의 기록(본·사후모임) ③ 코치 한마디(다음 질문 제안, 누르면 입력칸에 들어감) ④ 신청서 요약과 전문 보기.
- 가로 720~1099: 노트는 머리줄의 "노트" 단추로 여닫는 옆 서랍.

**질문 칸(PC·휴대전화 공통 생각)**
- 제안 문장 4개를 전체 글로 보여 준다(잘라 내지 않음). **누르면 바로 보낸다.** 각 제안 옆 연필은 "입력칸에 넣어 고쳐 쓰기".
- 그 아래 입력줄 하나: 글 입력(Enter 보내기, Shift+Enter 줄바꿈) · 마이크 · 보내기. "고르기/직접 입력" 전환은 없앤다.
- "다른 제안"은 제안 머리의 ↻ 하나.
- 보낸 내 말 말풍선 아래에 **되돌리기**(마지막 말에만). 되돌리면 그 말과 답이 지워지고 글이 입력칸으로 돌아온다(지운 대화는 회고에 남김, 지금과 같음).
- PC 키보드: 1–4는 그 제안을 바로 보냄, 입력칸에서 Enter.

**휴대전화(가로 720 미만)**
- 머리줄: ← · 제목 · 단계(사전 1/3 같은 짧은 표시) · 노트(남은 확인 수 표시) · 마치기.
- 무대 띠(화면의 약 20%, 얼굴은 무대 위에) → 대화 기록(남는 높이) → 질문 칸: 제안은 가로로 미는 카드(카드 하나에 전체 글, 옆 카드가 살짝 보임), 누르면 보냄 · 연필로 고쳐 쓰기 → 입력줄.
- 노트는 아래에서 올라오는 판(머리줄의 노트).

**단계 관문(사용자 선택: 관문 유지, 늘 펼친 체크)**
- 사전모임: 피해 학생 참여 의사, 행동한 학생 참여 의사, 학생·보호자 동의 범위, 현재 안전과 대면 준비 — 4개 모두 체크해야 다음 단계. 본모임: 각자 확인 체크 + 합의 내용 + 점검 계획. 지금 규칙(engine.js canAdvance) 그대로.
- PC는 노트에 늘 펼쳐 있어 여닫는 클릭이 없다. 휴대전화는 노트 판에서.
- "중단이 필요한 순간" 조건은 지금처럼 다음 단계 대신 보류 안내.

**마치기**
- 마치기 한 번이면 곧바로 회고. 결과(관계회복 진전 등 5가지)는 회고 맨 위의 칩으로 고른다(기본값: 중단 조건이면 "안전을 위한 보류·중단", 사후모임까지 갔으면 "관계회복 진전·실천 확인", 그 밖은 "부분 진전·추가 모임 필요"). 결과 창 없음.

### 3.4 회고
- PC 한 화면 세 칸(칸 안 스크롤): 머리줄(사례·결과 칩·다시 연습·인쇄·내려받기·AI 심층 회고) / 왼쪽 돌아보기(요약, 이어갈 점, 다시 살펴볼 점, 다음 연습) / 가운데 장면(대화에서 찾은 장면, ▶를 누르면 그 칸 위의 작은 무대에서 다시 봄 — 창 없음) / 오른쪽 나의 회고(입력하면 자동 저장)·다시 해 본 질문·전체 대화.
- 휴대전화: 같은 순서로 쌓되 각 덩어리는 짧게.
- 인쇄·PDF는 지금 인쇄 스타일을 새 구조에 맞춰 유지.

### 3.5 기록
- 자동 저장된 연습 목록(최신 20개): 사례·날짜·단계/결과. 한 번 눌러 이어하기 또는 회고 보기. 삭제는 확인 창 대신 "삭제했어요 · 되돌리기" 알림.

### 3.6 도움말·설정
- 도움말: 한 화면 짧은 안내.
- 설정: 오른쪽(휴대전화는 아래) 판. 대화 방식(체험/AI), 제공사·모델·키·연결 확인, 3D 장면(자동/켜기/끄기), 목소리, 효과음, 글자 크기. 바꾸면 바로 적용(저장 단추 없음, 키 연결 확인만 단추).

## 4. 지키는 것(이전 검사가 지키던 동작)
사례 검색·필터, 사전모임의 학생별 분리와 학생별 입력 초안, 세 제공사 AI 호출과 오류 안내(HTTP 번호별 문구, 일시 오류 재시도), 오류 시 보낸 문장이 입력칸으로 돌아옴, API 키는 저장하지 않음, 음성 입력(자동 전송 없음, 권한 거부 안내), 안전 보류, 동의·합의 관문, 내려받기·AI 회고·인쇄·장면 다시 보기·질문 되돌리기, 3D 무대 전체(문맥 복구·느린 기기·그림 무대), 글자 크기 유지, 동작 줄이기, 320~1440px, HTML 이스케이프, 페이지 오류 없음, CSP(script/style 'self').

## 5. 일부러 바꾸는 것
- 제안 문장은 누르면 바로 보낸다(이전: 고르기만으로는 보내지 않음). 되돌리기가 확인을 대신한다.
- 자동 저장(이전: 기록 저장 단추와 저장 상태 표시).
- 신청서 관문 없음, 결과 고르기 창 없음, 시작 조건 창 없음, 입력 방식 전환 없음.
- 첫 화면 3D 미리보기 없음.

## 6. 만드는 방법(설계자 판단)
- 화면 코드를 새로 쓴다: `public/app.js`(상태·동작·이벤트)와 화면별 모듈 `public/views/*.js`, 새 스타일 `public/styles/app.css` 하나(+무대 `stage.css`, 인쇄 `print.css`는 새 구조에 맞게). 이전 화면 모듈과 스타일(application-view.js, experience.js의 화면 부분, base/shell/library/room/review/application.css)은 지운다.
- 로직 모듈은 그대로 쓴다: scenarios, engine, questions, premeeting, application(데이터), workspace, retry, replay, sounds, followups, stage/*.
- 브라우저 검사는 새 화면에 맞춰 새로 쓴다(`tests/ui-browser.mjs` 등). 무대 실험실 검사는 그대로, 앱 화면에 기대는 무대 검사 항목은 새 화면에 맞춘다. Node 검사(로직)는 그대로 통과해야 한다.
- 버전 1.0.0.

## 7. 만드는 사람에게 맡기는 것
정확한 크기·색 조정, 애니메이션 곡선, 파일 나누기, 문구 다듬기(뜻은 유지).
