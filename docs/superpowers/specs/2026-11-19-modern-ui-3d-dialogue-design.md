# 다시, 대화 v0.4 설계: 새 화면 디자인과 3D 대화 장면

- 작성일: 2026-11-19
- 대상 저장소: `doguri25/dasi-dialogue` (현재 v0.3.1)
- 참고 엔진: `doguri25/pokju-edu` 「폭주 구구단」 정식 버전 1.5 (Three.js r187, Vite 빌드). 그 저장소는 읽기만 하고 고치지 않는다.

## 1. 무엇을, 왜

관계회복지원단 교사가 가상 학생·보호자와 대화모임을 연습하는 앱이다. 사용자 요청은 두 가지다.

1. 앱의 UI·UX 전체를 요즘 잘 만든 서비스 수준의 현대적인 디자인으로 바꾼다.
2. 대화 장면을 폭주 구구단의 3D 엔진으로 만들고, 화면 속 학생이 실제로 대화하는 것처럼 캐릭터를 구현한다.

"실제로 대화하는 것처럼"이 무엇을 뜻하는지 묻자 사용자는 **두 가지 모두**라고 답했다.

- **몸짓을 읽는 연습:** 시선 회피, 머뭇거림, 팔짱, 움츠림처럼 말로 드러나지 않는 신호를 교사가 화면에서 읽을 수 있어야 한다. 관계회복 모임에서 진행자가 실제로 살피는 것이다.
- **생생한 몰입:** 입 모양이 말에 맞춰 움직이고, 눈을 깜빡이고, 숨 쉬고, 말하는 사람에게 화면이 향해야 한다.

지금 대화 화면은 말풍선과 작은 학생 사진(2D 점토 그림)뿐이다. 교사는 학생의 말을 글로만 읽는다.

## 2. 목표 · 하지 않을 것 · 실패로 볼 것

### 목표

- 모든 화면(사례 목록, 사례 상세, 신청서, 연습실, 회고, 기록, 가이드, 설정·대화창)을 하나의 새 디자인 체계로 바꾼다.
- 연습실에 3D 대화 장면(이하 **무대**)을 둔다. 폭주 구구단과 같은 렌더링 구성을 쓴다: Three.js r187, sRGB 출력, ACES 톤 매핑, EffectComposer → 빛 번짐(UnrealBloom) → GLSL 색 보정 패스 → OutputPass, PMREM 환경광, 자동 화질, WebGL 문맥 손실 대응, 시작 시 셰이더 미리 컴파일.
- 캐릭터는 매 답변의 **감정(mood)** 에 맞는 몸짓을 하고, 말하는 동안 한글 음절에 맞춰 입을 움직인다.
- 지금 되는 것은 모두 유지한다: 사전·본·사후모임 흐름, 질문 고르기와 직접 입력·마이크, 저장·재개·내보내기, Claude·Gemini·OpenAI 연결, 시나리오 체험, 큰 글자, 효과음, 답변 읽어주기, 모바일 구성, 동작 줄이기, 빌드 없는 배포.

### 하지 않을 것

- 새 음성 합성 서비스나 목소리 복제. 소리는 지금처럼 브라우저 `speechSynthesis`(답변 읽어주기)만 쓴다.
- 점수, 승패, 게임 요소.
- 대화 흐름 규칙(단계, 진행 확인, 합의, 사전면담 격리) 변경. 바뀌는 것은 답변 데이터에 `mood`가 붙는 것뿐이다.
- 폭주 구구단의 게임 코드 이식. 렌더링 구성, 셰이더 아이디어, 화질·문맥 손실 대응 방식만 가져온다.
- 외부 3D 모델 파일 사용.

### 실패로 볼 것 (기술적으로 돌아가더라도)

- 3D 때문에 연습이 막히는 것. 무대가 없거나 느리거나 고장 나도 글과 버튼만으로 끝까지 연습할 수 있어야 한다. 보내기·고르기는 애니메이션을 기다리지 않는다.
- 학교 크롬북·보급형 태블릿에서 화면이 버벅여 쓸 수 없게 되는 것.
- 캐릭터가 희화화되는 것. 행동한 학생을 악당처럼, 피해 경험 학생을 울보처럼 만들지 않는다. 기존 그림 프롬프트의 원칙(차분하고 존중받는 얼굴, 과장 없는 표정)을 그대로 따른다.
- 섬뜩하거나 어색한 얼굴(불쾌한 골짜기).
- 무대에 "방어적", "불안함" 같은 감정 이름표를 붙여 정답처럼 보여 주는 것. 교사는 몸짓을 직접 읽는다. 기존 코치 관찰 문장은 그대로 둔다.
- 큰 글자, 채워진 색 면, 키보드 초점 표시 같은 접근성 원칙이 디자인 때문에 약해지는 것.

## 3. 제약

- **빌드 단계 없음:** Node.js 22 이상이면 설치 없이 `npm start`로 실행된다. GitHub Pages와 Vercel은 `public/`을 그대로 배포한다. 이 성질을 유지한다.
- **화면 갱신 방식:** `render()`가 매번 `#app`의 `innerHTML`을 통째로 바꾼다. WebGL 캔버스를 그 안에 두면 매번 사라진다. 무대는 한 번 만든 요소를 유지하고, `render()` 뒤에 새 자리(`#stage-slot`)로 옮겨 붙인다. 옮겨도 WebGL 문맥은 유지된다.
- **사용자:** 기기에 익숙하지 않은 교사. 본문 18px(크게 21px), 주요 버튼 높이 54px 이상, 색 면으로 구분, 분명한 초점 표시(`docs/UI-DIRECTION.md`).
- **기기:** 학교 크롬북, 태블릿, 오래된 노트북. WebGL2가 없거나 느릴 수 있다.
- **검사:** `npm test`(Node 단위·HTTP)는 CI에서 돌고, 브라우저 검사 8개(`tests/*.mjs`)는 Playwright로 따로 돈다. 바뀐 화면에 맞춰 검사도 고치고 모두 통과해야 한다.
- **개인정보:** API 키는 지금처럼 메모리에만 두고 저장하지 않는다. 새로 생기는 외부 요청은 없다. 글꼴도 저장소에 넣는다(6.2).

## 4. 방법 비교

### 4.1 캐릭터를 만드는 방법

| 방법 | 내용 | 장점 | 단점 |
| --- | --- | --- | --- |
| **A. 3D 점토 캐릭터를 직접 만듦 (선택)** | 폭주 구구단이 차를 도형으로 깎아 만들듯 Three.js 도형으로 머리·머리카락·눈·눈썹·입·몸·팔을 만들고 관절로 움직인다 | 입 모양, 깜빡임, 시선, 자세, 손짓을 모두 실시간으로 바꿀 수 있다. 기존 그림이 "매트 클레이 3D" 화풍이라 이어진다. 내려받을 모델이 없어 가볍다 | 코드가 가장 많다. 얼굴을 귀엽게 다듬지 않으면 어색하다 |
| B. 기존 그림을 3D 방에 세워 움직임 | 그림 판을 셰이더로 숨 쉬듯 흔들고 입을 덧그린다 | 그림체가 그대로, 빠르다 | 시선·자세를 못 바꾼다. 입 덧그림이 티 난다. 몸짓 읽기가 거의 안 된다 |
| C. 외부 3D 인물 모델 | 표정 움직임이 있는 GLB 모델을 받아 씀 | 가장 사실적 | 맞는 무료 모델이 드물다. 한 명에 수 MB. 점토 화풍과 충돌 |

사용자는 결과만 말하고 방법을 맡겼다("찾아서 구현해줘", "둘 다"). B는 몸짓 읽기라는 목표에 맞지 않고, C는 학교 기기와 화풍에 맞지 않는다. **A를 고른 것은 설계자의 판단이다.**

### 4.2 Three.js를 들여오는 방법

| 방법 | 장점 | 단점 |
| --- | --- | --- |
| **필요한 부분만 묶은 파일 하나를 `public/vendor/`에 넣음 (선택)** | 빌드 없는 배포 유지, 오프라인 로컬 실행 가능, 오래된 브라우저(import map 미지원)도 동작 | 파일 약 700KB를 저장소에 둔다(압축 전송 시 약 170KB) |

| CDN과 import map | 저장소가 가볍다 | 오프라인 로컬 실행 불가, iPadOS 15 이하에서 import map 미지원 |

## 5. 대화 장면 설계

### 5.1 무대가 하는 일 (교사가 겪는 흐름)

1. 연습실에 들어가면 무대에 대화실이 보이고, 지금 만나는 학생이 탁자 건너편에 앉아 있다. 숨 쉬고 깜빡이며 가끔 시선을 옮긴다. 교사의 자리는 카메라다(1인칭).
2. 교사가 질문을 보내면 무대 아래 자막에 "나: …"가 잠깐 뜨고, 학생은 교사를 보며 **듣는다**(작은 끄덕임, 고개 기울임). 마이크로 말하는 동안에도 듣는 자세를 한다.
3. 답을 기다리는 동안 학생은 **생각한다**(시선이 옆이나 아래로, 입술을 다묾). 지금의 "이야기를 생각하고 있어요" 점 세 개를 대신한다(글 안내는 화면 읽기용으로 남김).
4. 답이 오면 학생이 **말한다.** 그 답의 감정에 맞는 자세로 바뀌고, 한 음절씩 입이 움직이며, 자막이 말하는 속도에 맞춰 나타난다. 쉼표·마침표·말줄임표에서 쉰다.
5. 본모임·사후모임에서 여러 사람이 답하면 한 사람씩 차례로 말한다. 카메라가 말하는 사람 쪽으로 부드럽게 옮겨 가고, 듣는 사람은 말하는 사람을 보거나 교사를 힐끗 본다.
6. 말하는 도중에 교사가 다음 질문을 보내면 캐릭터는 말을 맺고 바로 듣는 자세로 돌아간다. 무대는 교사를 기다리게 하지 않는다.
7. **자막 넘기기**를 누르면 현재 줄이 한 번에 다 나온다.

대화 기록(말풍선 목록)은 무대 아래에 그대로 둔다. 답변 전문은 도착하는 즉시 기록에 들어간다. 교사가 자기 속도로 읽을 수 있어야 하기 때문이다. 무대 자막은 "지금 말하는 장면", 기록은 "지난 대화"다.

### 5.2 감정(mood)

답변마다 감정 하나를 붙인다. 값은 아래 8가지로 고정한다.

| 값 | 뜻 | 시선 | 자세·팔 | 얼굴 | 말하기 |
| --- | --- | --- | --- | --- | --- |
| `calm` | 차분함 | 교사를 자주 봄 | 바로 앉음, 손은 탁자 위 | 편한 눈썹, 다문 입 | 보통 속도 |
| `open` | 마음을 엶 | 눈을 맞춤, 끄덕임 | 앞으로 조금 기욺, 말하며 손짓 | 부드러운 미소 | 보통 속도 |
| `hesitant` | 망설임 | 말 시작 전 아래를 봄 | 손가락을 만지작거림, 고개 기울임 | 눈썹 안쪽이 살짝 올라감 | 느림, 첫마디 전 쉼 |
| `anxious` | 불안함 | 자주 피하고 빨리 깜빡임 | 어깨가 올라감, 두 손을 모아 쥠 | 눈썹이 올라가고 입꼬리가 긴장 | 조금 빠름, 짧은 쉼이 잦음 |
| `defensive` | 방어함 | 옆을 봄, 짧게 노려보지 않고 피함 | 뒤로 기댐, 팔짱 | 눈썹이 내려가고 입을 꾹 다묾 | 조금 빠름, 짧게 끊음 |
| `upset` | 속상함 | 아래를 봄 | 어깨가 처짐 | 눈썹 안쪽이 올라가고 입꼬리가 내려감 | 느림 |
| `withdrawn` | 위축·거리 두기 | 거의 안 봄 | 몸을 옆으로 돌리고 웅크림, 무릎 위 손 | 표정이 작음 | 아주 느림, 입 움직임이 작음 |
| `relieved` | 안도함 | 다시 눈을 맞춤 | 숨을 내쉬며 어깨가 내려감 | 옅은 미소 | 보통 속도 |

- 강도(0~1)는 따로 받지 않고 `risk`로 정한다: `none` 0.55, `tension` 0.8, `stop` 1.0.
- **AI 모드:** `lib/prompts.mjs`의 출력 형식에 `messages[].mood`를 더하고 8가지 값과 짧은 뜻을 알려 준다. "학생 반응 관찰(observation)과 같은 방향으로 고르라"고 덧붙인다. `validateReply`는 모르는 값이나 빈 값이면 아래 추정 규칙으로 채운다. 그래서 예전 형식의 응답도 그대로 동작한다.
- **시나리오 체험:** `demoReply`가 의도(`classify`), 조건(variant), 역할, 단계로 정한다. 예: 압박 표현 → 피해 경험 학생 `upset`, 행동한 학생 `defensive`. 중단 조건 → `anxious`·`withdrawn`. 방어·교착 초반 → 행동한 학생 `defensive`, 피해 경험 학생 `hesitant`. 감정 질문·필요 질문 → `open`. 안전 확인 → `relieved`. 사후 미이행 → `hesitant`. 표 전체는 `public/stage/mood.js`에 둔다.
- **추정 규칙(공통):** `stop` → 피해 경험 학생 `withdrawn`, 그 외 `anxious`. `tension` → 행동한 학생 `defensive`, 그 외 `hesitant`. `none` → `calm`. 이 규칙은 서버(`lib/prompts.mjs`)와 브라우저가 같은 모듈을 쓴다(지금도 서버가 `public/scenarios.js`를 가져다 쓴다).
- 감정은 참여자 메시지에 `mood`로 저장한다. 저장·재개, 대상 바꾸기, 단계 이동 뒤에도 캐릭터는 마지막 감정의 자세로 앉아 있다. 예전 기록에 `mood`가 없으면 추정 규칙을 쓴다.

### 5.3 입 모양 (한글 음절 → 입 모양)

`public/stage/hangul.js`는 문장을 말하기 시간표로 바꾸는 순수 함수다(Node에서 단위 검사).

- 한글 음절(U+AC00~U+D7A3)을 초성·중성·종성으로 나눈다.
- 중성으로 입 모양을 정한다: ㅏ·ㅑ·ㅐ·ㅒ·ㅘ·ㅙ → `A`(크게 벌림), ㅓ·ㅕ·ㅔ·ㅖ·ㅝ·ㅞ → `E`(중간), ㅗ·ㅛ·ㅚ → `O`(둥글게), ㅜ·ㅠ·ㅟ → `U`(작고 둥글게), ㅡ·ㅢ → `EU`(납작하게), ㅣ → `I`(옆으로 넓게).
- 초성이 ㅁ·ㅂ·ㅃ·ㅍ이면 음절 앞에 잠깐 입을 닫고(`M`), 종성이 ㅁ·ㅂ이면 음절 끝에 닫는다.
- 기본 한 음절 140ms에 감정별 속도를 곱한다. 띄어쓰기 40ms, 쉼표 220ms, 마침표·물음표·느낌표 380ms, 말줄임표 600ms를 쉰다. 숫자·영문은 일반적인 열고 닫기로 처리한다.
- 결과는 `[{start, duration, shape, open, charIndex}]`이고, 자막은 `charIndex`로 한 글자씩 나타난다.
- **답변 읽어주기가 켜져 있으면** 문장마다 `SpeechSynthesisUtterance`로 읽는다. 학생은 높게, 보호자는 낮게(pitch), 감정별 속도(rate)를 준다. 브라우저가 `boundary` 이벤트를 주면 그 위치로 시간표를 맞추고, 안 주면 시간표대로 움직이며 `end`에서 마친다. 소리를 켰다고 자동 재생이 막히지 않도록, 사용자가 보내기를 누른 동작 안에서 읽기를 시작한다(지금과 같다).

### 5.4 캐릭터

- **생김새는 기존 그림을 그대로 옮긴다.** 그림 6장(학교급별 2명)의 머리 모양·옷과 같은 조합을 `public/stage/looks.js`에 데이터로 적는다. 어느 학생이 어느 생김새인지는 지금의 `portraitFor` 규칙(사례 번호 짝홀로 바꿈)을 그대로 따른다. 그래서 목록 카드·신청서·기록의 사진 속 아이가 무대에도 앉아 있다.

  | 그림 | 머리 | 옷 |
  | --- | --- | --- |
  | 초등 a | 짧은 단발 | 세이지 초록 맨투맨 |
  | 초등 b | 짧고 살짝 헝클어진 머리 | 황토색 맨투맨 |
  | 중등 a | 어깨 길이, 반묶음 | 세이지 가디건 + 크림색 셔츠 |
  | 중등 b | 짧게 다듬은 머리 | 연보라 후드 |
  | 고등 a | 턱선 단발 | 세이지 가디건 + 흰 셔츠 |
  | 고등 b | 짧은 옆 가르마 | 남색 재킷 + 크림색 셔츠(로고 없음) |

- **보호자**는 새로 만든다. 성별을 드러내지 않는 차분한 어른(짧은 머리, 베이지 니트). 지금 2D에서는 글자 "보" 아바타라, 2D 쪽도 보호자 그림 대신 기존 글자 아바타를 유지한다.
- **화풍:** 매트 클레이. 둥근 형태, 거친 정도가 높은 재질(roughness 약 0.8)에 약한 광택(sheen)을 더해 점토 표면처럼 보이게 한다. 머리가 큰 귀여운 비율로 하되 학교급마다 키와 비율을 달리한다(초등이 가장 작고 머리 비율이 크다).
- **얼굴 장치:** 흰자·갈색 홍채·반사광이 있는 눈, 깜빡이는 눈꺼풀, 눈썹 2개(각도·높이로 감정 표현), 입(입 모양별로 벌림·너비·둥글기를 조절), 작은 코, 볼 홍조. 시선은 눈동자와 머리가 함께 움직인다.
- **몸:** 앉은 자세. 목·몸통·어깨·위팔·아래팔·손을 관절로 이어 팔짱, 탁자 위 손, 무릎 위 손, 두 손 모으기, 만지작거리기, 말하며 손짓하기를 표현한다. 손은 점토 화풍에 맞는 둥근 벙어리장갑 형태다.
- **늘 하는 움직임:** 숨쉬기(어깨·가슴), 2~6초 간격의 불규칙한 깜빡임, 작은 시선 이동, 가끔 자세 고쳐 앉기. 같은 동작을 똑같이 반복하지 않도록 매번 조금씩 다르게 한다.
- **자세 전환:** 감정이 바뀌면 0.6~1.2초에 걸쳐 부드럽게 옮겨 간다. 감정·상태(듣기·생각·말하기·대기)별 목표 자세는 `public/stage/acting.js`에 표로 둔다.

### 5.5 대화실과 카메라

- **방:** 관계회복 대화실. 밝은 나무 원탁, 의자, 오후 햇빛이 드는 창(빛 번짐으로 은은하게 빛남), 책장, 화분, 러그, 세이지·크림 톤 벽. 기존 그림의 색(세이지, 연보라, 살구, 크림)을 쓴다. 소품은 적게 둬서 인물이 돋보이게 한다.
- **빛:** 하늘·바닥 반구광, 창 쪽 따뜻한 주광(부드러운 그림자), 보조광, PMREM 실내 환경광.
- **색 보정 패스:** 폭주 구구단 `grade.frag`의 구성(비네트, 필름 그레인, 따뜻한·차가운 색 기울임)을 대화실에 맞게 줄인다. 긴장 장면(`tension`·`stop`)에서는 아주 조금 차갑고 채도가 낮게, 안도 장면에서는 조금 따뜻하게 한다. 눈에 띄지 않을 정도로만 한다.
- **자리:** 사전모임은 일대일이다. 지금 만나는 사람만 탁자 건너편에 앉는다. 본모임·사후모임은 원형으로 앉는다: 피해 경험 학생은 왼쪽 앞, 행동한 학생은 오른쪽 앞, 보호자는 피해 경험 학생 옆. 교사의 자리가 카메라다.
- **카메라:** 사전모임은 상반신이 보이는 정면 구도. 여러 명일 때는 넓게 잡았다가 말하는 사람 쪽으로 1.2초 동안 부드럽게 옮긴다(장면을 끊어 바꾸지 않음). 아주 작은 손떨림 같은 흔들림을 준다. 휴대전화 세로 화면에서는 화각과 구도를 다시 맞춘다.

### 5.6 화질과 안전장치

- **켜는 조건:** 설정에 "3D 대화 장면: 자동 / 켜기 / 끄기"를 두고 이 브라우저에 기억한다(`dasi.stage`). "자동"은 WebGL2가 있고, 데이터 절약 모드가 아니고, `navigator.deviceMemory`를 알 수 있으면 2GB 이상일 때 켠다. 무대 구석에도 "3D 끄기/켜기"를 둔다.
- **늦게 불러오기:** 3D 코드와 Three.js 묶음 파일은 무대가 필요할 때만 `import()`로 불러온다. 사례 목록을 처음 열 때 3D 파일을 받지 않는다.
- **자동 화질:** 프레임 시간의 중앙값을 보고 해상도 배율(1 → 0.85 → 0.7)을 먼저 낮춘다. 그래도 느리면 그림자, 그다음 빛 번짐을 끈다. 빨라지면 다시 올린다. 기기 픽셀 배율은 PC 1.5, 휴대전화 1.25까지만 쓴다.
- **쉬기:** 무대가 화면 밖에 있거나(IntersectionObserver), 탭이 숨겨졌거나, 대화창(모달)이 열려 있으면 그리지 않는다. 아무도 말하지 않을 때는 초당 30프레임으로 줄인다.
- **문맥 손실:** WebGL 문맥이 끊기면 그리기를 멈추고 2D 무대로 바꾼다. 돌아오면 화질을 한 단계 낮춰 다시 만든다.
- **고장:** 무대 코드의 어떤 오류도 앱으로 번지지 않는다. 초기화가 실패하면 2D 무대로 바꾸고 한 번만 짧게 알린다.
- **2D 무대:** 3D를 쓸 수 없거나 끈 경우의 무대다. 기존 학생 그림을 크게 보여 주고 숨쉬기(살짝 커졌다 작아짐), 말할 때 테두리가 퍼지는 표시, 같은 자막을 쓴다. 흐름과 자막은 3D와 똑같다.
- **동작 줄이기:** 카메라 이동과 흔들림을 끄고 자세 전환을 짧게 한다. 자막은 한 번에 다 나온다. 깜빡임과 작은 입 움직임은 남긴다(말하는 사람을 알리는 정보이기 때문이다).
- **시험용 상태 표시:** 무대 요소에 `data-stage-mode="3d|2d|off"`, `data-stage-state="idle|listening|thinking|speaking"`, `data-speaker`, `data-mood`를 붙인다. 화면 읽기 프로그램에는 무대를 장식으로 숨기고(`aria-hidden`), 자막과 대화 기록이 정보를 전한다.

### 5.7 앱과 무대를 잇는 방법

무대는 `public/stage/`의 모듈이 맡고, `app.js`는 아래 함수만 부른다.

| 때 | `app.js`가 부르는 것 |
| --- | --- |
| `render()` 직후, 연습실이면 | `stage.attach(slot)`: 유지 중인 무대 요소를 새 자리로 옮김 |
| 대상·단계 변경, 재개 | `stage.setCast({scenario, phase, target, lastMoods})` |
| 교사 발언 전송 | `stage.teacherSaid(text)` → 듣기 |
| 답 기다리는 중 | `stage.think()` |
| 답 도착 | `stage.speak(messages, {tts})`: 메시지마다 `{speaker, text, mood}`, 차례로 말함 |
| 마이크 녹음 시작·끝 | `stage.listen(true/false)` |
| 연습실을 떠남 | `stage.detach()`: 그리기를 멈추고 요소는 유지 |

- 지금 `sendMessage`에 있는 `speechSynthesis` 읽기는 무대의 말하기로 옮긴다. 무대가 꺼져 있으면 2D 무대가 같은 일을 한다.
- 대상 선택은 지금의 `<select id="target">` 대신 **얼굴 칩**(라디오 묶음, `name="target"`)으로 바꾼다. 무대 위 캐릭터를 눌러도 같은 대상이 선택된다.

## 6. 화면 디자인

### 6.1 방향: 따뜻한 연습 스튜디오

- **바탕:** 따뜻한 종이색(#F7F5F0) 위에 세이지·살구·연보라의 아주 옅고 흐린 빛 번짐을 깐다.
- **면:** 흰 카드, 큰 둥근 모서리(20~28px), 겹겹의 부드러운 그림자. 선 대신 면과 간격으로 나눈다는 원칙을 유지한다.
- **색:** 기본은 깊은 숲 초록(#1E4D43, 누름 #163B33). 갈등 주제 7색과 난도 점 표시는 유지하되 채도를 다듬는다. 경고는 벽돌색, 선택은 진한 초록 면 + 흰 글자 + "선택됨" 글자(지금 원칙 유지).
- **글자:** Pretendard Variable(6.2), 본문 18px / 크게 21px. 큰 제목은 굵고 자간을 조금 좁힌다. 숫자는 고정폭 숫자.
- **움직임:** 화면 전환은 지원하는 브라우저에서 View Transitions API, 아니면 지금처럼 짧은 페이드. 누르면 살짝 눌리는 버튼, 카드에 올리면 살짝 뜨는 효과. 모두 동작 줄이기를 따른다.
- **대화창(모달):** PC는 가운데 카드, 휴대전화는 아래에서 올라오는 시트. 뒤 배경은 흐리게.

### 6.2 글꼴

Pretendard Variable 1.3.9(SIL OFL)의 동적 부분 글꼴을 npm 패키지에서 꺼내 `public/vendor/pretendard/`에 넣는다(woff2 약 3.1MB, CSS의 `unicode-range` 덕분에 브라우저는 화면에 쓰인 글자 묶음만 받는다). CDN을 쓰지 않으므로 외부 요청이 없고, 로컬 실행·오프라인에서도 같은 글꼴로 보인다. 글꼴을 못 읽으면 지금의 시스템 고딕(Apple SD Gothic Neo, Noto Sans KR, Malgun Gothic)으로 보인다. 라이선스 파일을 함께 둔다.

### 6.3 탐색

- **PC:** 무거운 왼쪽 초록 사이드바를 없앤다. 위쪽에 반투명 앱 바(`.topbar`)를 두고 로고, 탐색 알약 탭(사례 둘러보기 · 진행 중인 모임 · 내 연습 기록 · 진행 가이드), 효과음 · 글자 크게 · AI 연결을 둔다. 연습실에서 무대와 질문 영역이 가로 폭을 다 쓰게 하려는 것이다.
- **휴대전화·태블릿(900px 이하):** 지금처럼 아래쪽 고정 탐색(사례 / 연습 / 기록 / 도움말)을 반투명 막대로 다듬는다.

│ [자막 넘기기]          [소리] [3D 끄기]     │ │ 3  ││ 4  │              │
├──── 대화 기록 (스크롤) ─────────────────────┤ └────┘└────┘              │
│  말풍선…                                    │ 다른 질문 보기 · 예시 전체 │
│                                            │ [문장 고쳐 쓰기] [보내기 ▶] │
└────────────────────────────────────────────┴───────────────────────────┘
```

- 창 높이 560px 이상에서는 지금처럼 페이지 전체가 스크롤되지 않는다. 무대, 대화 기록, 질문 카드, 보내기 버튼이 모두 화면 안에 있다. 무대와 기록은 왼쪽 칸 높이를 나눠 쓴다(무대는 최소 260px).
- 사전모임 안내 순서(대화모임 안내 → 무슨 일이 있었니?)는 무대 위쪽에 작은 단계 표시로 둔다.
- 진행 확인·메모는 지금처럼 오른쪽 칸을 바꿔 보여 준다.
- 연습실의 모든 기존 기능 버튼(전체 대화, 답변 읽어주기 등)은 자리만 옮기고 남긴다.

```

- 무대는 폭에 맞춘 16:10, 최대 화면 높이의 45%. 그 아래로 지금처럼 기록과 질문이 이어지고 페이지가 스크롤된다.
- 대화 연습 / 진행 확인 전환은 유지한다.

**회고:** 위쪽 결과 카드, 잘한 점·다음에 해 볼 점 카드, 대화에서 찾은 장면 인용, 내려받기.

**기록·가이드:** 같은 카드 체계로 정리한다.

## 7. 검사와 확인

- **단위 검사(Node, `npm test`):** `hangul.js`(음절 분해, 입 모양, 쉼, 글자 위치), `mood.js`(정규화, 추정, 체험 감정 표), `looks.js`(역할 대응이 `portraitFor`와 같음), 프롬프트에 `mood`가 들어감, `validateReply`의 `mood` 정규화, `demoReply`가 `mood`를 줌, 저장·재개 시 `mood` 유지.
- **브라우저 검사:** 기존 8개를 새 화면에 맞게 고친다(얼굴 칩 대상 선택, 사이드바 대신 앱 바 등). 새 `tests/stage-browser.mjs`:
  - WebGL 켬: 캔버스가 있고 프레임이 진행됨, 답이 오면 `speaking` → `idle`, 자막이 답 전문과 같아짐, 자막 넘기기, 말하는 중 다음 질문 → `listening`, 여럿이 말할 때 차례.
  - 3D 끔과 WebGL 없음(실행 옵션으로 막음): 2D 무대가 나오고 흐름이 같음.
  - 문맥 손실(`WEBGL_lose_context`)을 일으키면 2D로 바뀌고 오류가 없음.
  - 동작 줄이기: 자막이 한 번에 나옴.
  - 페이지 오류 없음. PC·휴대전화 화면 사진을 남김.
- **크기 기준:** 묶음 파일 800KB 이하. 사례 목록 첫 화면에서 3D 파일을 받지 않음.
- **문서:** README(3D 대화 장면, 설정), `docs/UI-DIRECTION.md`(새 방향), CHANGELOG(v0.4.0), `public/version.js`를 0.4.0으로, `docs/VERIFICATION.md`에 검사 결과, `docs/screenshots/` 새 사진.

## 8. 설계자가 정한 것 (사용자 확인 전)

- 캐릭터 방법 A, Three.js 묶음 파일 방식, Pretendard 글꼴을 저장소에 넣음.
- 대화 기록은 즉시 전문을 보여 주고, 무대 자막은 말하는 속도로 나타남.
- 소리는 지금처럼 "답변 읽어주기"를 켰을 때만 남(학교·사무실 소음 고려). 무대에 켜고 끄는 버튼을 눈에 띄게 둔다.
- 감정 이름표는 화면에 보이지 않음.
- PC는 사이드바 대신 위쪽 앱 바.
- 사례 목록 첫 카드에 3D 미리보기(PC·태블릿, 3D 켜짐일 때만).
- 대상 선택을 얼굴 칩으로 바꿈.
